# Подробная установка (Mac, Apple Silicon)

Пошаговая инструкция для локального запуска на Mac с Apple Silicon (M1, M2, M3 и новее) в VS Code. Команды ниже выполняются в **терминале**, а Python-код — в **ячейках ноутбука**.

## 1. Что находится в проекте

- `notebooks/01_mini_blip_flickr.ipynb` — обучение мини-BLIP на Flickr30k, поиск изображений по тексту, генерация подписей и CapFilt.
- `notebooks/02_medical_roco.ipynb` — та же работа плюс медицинская часть на ROCO. Для медицинской части нужны переменные и функции из предыдущих разделов, поэтому запускайте этот ноутбук с начала.
- `pyproject.toml` — список зависимостей проекта и требования к Python.
- `uv.lock` — точные версии зависимостей, выбранные менеджером `uv`.
- `.python-version` — выбранная версия Python.

Не запускайте обучение в двух ноутбуках одновременно: они используют память компьютера и могут записывать результаты в одни и те же папки.

## 2. Что такое окружение и зачем нужен uv

**Окружение** — отдельный набор Python и библиотек для проекта. Библиотеки из него не смешиваются с библиотеками других работ.

**uv** устанавливает Python, создаёт окружение и управляет зависимостями:

| Команда | Что делает |
| --- | --- |
| `uv python install 3.11` | Устанавливает Python 3.11 |
| `uv python pin 3.11` | Записывает выбор Python в `.python-version` |
| `uv add имя-пакета` | Добавляет библиотеку в проект и устанавливает её |
| `uv sync` | Восстанавливает окружение по файлам проекта |
| `uv run python` | Запускает Python из окружения проекта |

Для этой работы используем **Python 3.11**. Отдельно устанавливать его через Homebrew не требуется: это сделает `uv`.

## 3. Установите Homebrew и uv

Если Homebrew уже установлен, переходите к команде `brew install uv`.

Проверка Homebrew:

```bash
brew --version
```

Если терминал отвечает `command not found`, установите Homebrew:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Подключите Homebrew в текущем терминале:

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```

После установки Homebrew также выводит раздел **Next steps**. Выполните указанные там команды, чтобы `brew` был доступен и после открытия нового терминала.

Установите uv:

```bash
brew install uv
uv --version
```

## 4. Подготовьте Python и зависимости

Откройте папку проекта в VS Code и терминал через **Terminal → New Terminal**.

Перейдите в проект. На другом компьютере замените путь своим:

```bash
cd путь/к/mini-blip
```

Установите и закрепите Python 3.11:

```bash
uv python install 3.11
uv python pin 3.11
```

В этом проекте уже есть `pyproject.toml`, поэтому `uv init` повторно выполнять не нужно.

Создайте или обновите окружение именно на Python 3.11:

```bash
uv sync --python 3.11
```

Добавьте библиотеки для обоих ноутбуков:

```bash
uv add torch torchvision transformers datasets timm scikit-learn \
  pycocoevalcap numpy pandas matplotlib pillow tqdm ipywidgets
uv add --dev ipykernel
```

Эти команды нужны при первоначальной настройке: они сохраняют зависимости в `pyproject.toml` и обновляют `uv.lock`. Если зависимости уже записаны, для их восстановления достаточно `uv sync`.

Что устанавливается:

| Библиотеки | Назначение |
| --- | --- |
| `torch`, `torchvision` | Модели, обучение и обработка изображений |
| `transformers`, `timm` | Токенизаторы и предобученные модели/веса |
| `datasets` | Загрузка датасетов Hugging Face |
| `numpy`, `pandas`, `scikit-learn` | Вычисления, таблицы и метрики |
| `pycocoevalcap` | Метрики качества подписей |
| `matplotlib`, `pillow` | Графики и работа с изображениями |
| `tqdm`, `ipywidgets` | Индикаторы прогресса |
| `ipykernel` | Запуск Python-ячеек в ноутбуке |

Проверьте окружение:

```bash
uv run python --version
uv run python -c "import sys, torch, ipykernel; print(sys.executable); print('torch:', torch.__version__); print('MPS:', torch.backends.mps.is_available())"
```

Ожидается Python **3.11.x**, путь с **`.venv/bin/python`** и, при доступном ускорении Apple GPU, **`MPS: True`**. CUDA на Mac устанавливать не нужно.

## 5. Выберите ядро ноутбука в VS Code

Установите расширения **Python** и **Jupyter** от Microsoft, если их ещё нет.

1. Откройте нужный файл `.ipynb`.
2. Справа сверху нажмите **Select Kernel / Выбрать ядро**.
3. Выберите **Python Environments** и Python из папки проекта `.venv`.
4. Проверьте путь: `путь/к/mini-blip/.venv/bin/python`.

**Ядро** — Python-процесс, который выполняет ячейки. Важно выбрать окружение проекта: одинаковая надпись «Python 3.11» у двух вариантов не означает, что у них одинаковые библиотеки.

Если `.venv` не отображается:

1. Нажмите `Cmd + Shift + P`.
2. Выполните **Python: Select Interpreter**.
3. Выберите **Enter interpreter path…** и укажите путь к `.venv/bin/python`.
4. Повторно откройте выбор ядра ноутбука.

Если список не обновился, выполните **Developer: Reload Window** через `Cmd + Shift + P`.

При необходимости зарегистрируйте отдельное именованное ядро:

```bash
uv run python -m ipykernel install --user --name blip-mini --display-name "Python (blip-mini)"
```

После этого выберите **Python (blip-mini)** в списке ядер.

В новой ячейке ноутбука проверьте:

```python
import sys
print(sys.version)
print(sys.executable)
```

Должны появиться **3.11.x** и путь к **`.venv/bin/python`** в папке этой работы.

## 6. Подготовьте ноутбук к первому запуску

В конфигурации в начале выбранного ноутбука установите:

```python
QUICK = True
```

Это уменьшает данные и число эпох для проверки пайплайна. Время выполнения зависит от компьютера, загрузки данных и наличия сохранённых моделей; оценка времени из Colab не гарантируется на Mac.

В разделе установки найдите строку:

```python
sh(f'{sys.executable} -m pip install -q transformers datasets timm scikit-learn pycocoevalcap')
```

Закомментируйте её, если она ещё активна:

```python
# sh(f'{sys.executable} -m pip install -q transformers datasets timm scikit-learn pycocoevalcap')
```

Пакеты уже установлены через `uv`. В окружении uv может отсутствовать сам `pip`, поэтому эта строка может вызвать ошибку `No module named pip`.

На macOS для загрузчиков данных используйте **`NW = 0`**. Если в выбранном ноутбуке стоит:

```python
NW = min(4, os.cpu_count() or 1)
```

замените эту строку на:

```python
NW = 0
```

Это помогает избежать ошибок запуска дочерних процессов DataLoader из ноутбука. В медицинском ноутбуке уже есть условие, которое выбирает `0` вне Linux.

Сохраните ноутбук через `Cmd + S`.

## 7. Запустите работу

1. Убедитесь, что выбрано правильное ядро.
2. Выполняйте ячейки сверху вниз или нажмите **Run All**.
3. При первом запуске дождитесь загрузки датасетов и весов: нужен интернет и свободное место на диске.
4. Проверьте вывод раздела установки: на Apple Silicon медицинский ноутбук должен выбрать `device: mps`, если MPS доступен.
5. Если ячейка завершилась с ошибкой, исправьте её причину перед запуском следующих ячеек.

Старые таблицы и сообщения под ячейками могут быть сохранены из Colab. Например, вывод `Drive already mounted` сам по себе не означает, что текущий локальный запуск подключён к Google Drive.

После успешного пробного запуска можно поставить `QUICK = False`, перезапустить ядро через **Restart** и выполнить ноутбук с начала. Полный запуск обучает несколько моделей и требует существенно больше времени и памяти. Для длительных экспериментов можно использовать Colab с NVIDIA GPU; эта инструкция описывает локальное окружение Mac.

## 8. Где сохраняются результаты

При локальном запуске ноутбук выбирает пути относительно текущей рабочей папки:

| Папка | Содержимое |
| --- | --- |
| `blip_mini/checkpoints/` | Сохранённые модели основной части |
| `blip_mini/results/` | Метрики, таблицы и результаты основной части |
| `blip_mini/data/` | Архивы подвыборок данных |
| `blip_mini/med/` | Модели и результаты медицинской части |
| `blip_mini_local/images/` | Распакованные изображения |

При `QUICK = True` корневая папка результатов называется **`blip_mini_quick/`**. Поэтому готовые модели из `blip_mini/` не используются автоматически в пробном режиме.

Если есть архив с результатами из Google Drive, проверьте структуру после распаковки: папки `checkpoints/`, `results/`, `data/` должны находиться непосредственно внутри `blip_mini/`, без лишнего вложенного уровня.

По умолчанию ноутбук использует готовые чекпоинты и кэш результатов. Для намеренного повторного обучения основной части есть `FORCE_RETRAIN`, а для пересчёта медицинской части — `REDO`. Оставьте их равными `False` при обычном запуске.

## 9. Частые ошибки

### «Running cells requires the ipykernel package»

Чаще всего пакет установлен в одном окружении, а ядро выбрано из другого.

Нажмите **Cancel** в окне и выполните в терминале проекта:

```bash
uv python pin 3.11
uv sync --python 3.11
uv add --dev ipykernel
uv run python -c "import sys, ipykernel; print(sys.version); print(sys.executable)"
```

Заново выберите `.venv/bin/python` как ядро. Если раньше `.venv` использовала Python 3.15, `uv sync --python 3.11` пересоздаст её для выбранной версии; библиотеки восстановятся по настройкам проекта.

### `ModuleNotFoundError: No module named ...`

Проверьте `sys.executable` в ноутбуке. Если окружение правильное, добавьте нужную библиотеку из терминала:

```bash
uv add имя-пакета
```

Затем перезапустите ядро и выполните ячейки с начала. Название пакета при установке иногда отличается от импорта: `PIL` устанавливается как `pillow`, `sklearn` — как `scikit-learn`.

### В терминале видно `>>>`, а команды не работают

Вы находитесь внутри интерактивного Python. Выйдите командой:

```python
exit()
```

После появления обычного приглашения терминала можно вводить команды `uv`.

### Ошибка DataLoader или запуска дочерних процессов

Установите `NW = 0`, перезапустите ядро и выполните ячейки с начала.

### `scaled_dot_product_attention for MPS does not support dropout`

В обоих ноутбуках добавлен совместимый расчёт attention для MPS: dropout сохраняется, но применяется явно к весам внимания. После обновления файла перезапустите ядро и выполните ячейки с начала, чтобы старые экземпляры модели заменились новой реализацией.

Медицинский ноутбук также уменьшает обучающий батч мини-BLIP до 16 на MPS и использует меньшие батчи для оценки HF-BLIP и Bio_ClinicalBERT. Это снижает расход общей памяти Mac; эффективный батч мини-BLIP при этом отличается от исходной настройки CUDA.

### `Error loading @jupyter-widgets/base`

Это ошибка отображения интерактивных виджетов в VS Code. Сначала очистите старые выводы через **Clear All Outputs**, если сообщение относится к сохранённым результатам из Colab.

Если ошибка повторяется у новых выводов, можно разрешить загрузку JavaScript-файлов виджетов: `Cmd + Shift + P` → **Preferences: Open User Settings (JSON)**. Внутрь существующего объекта настроек добавьте:

```json
"jupyter.widgetScriptSources": ["jsdelivr.com", "unpkg.com"]
```

Между соседними настройками нужна запятая. После сохранения повторите ячейку. Проверьте, что эти сайты доступны через ваше интернет-соединение.

Для текстового прогресса без интерактивных виджетов замените импорты `from tqdm.auto import tqdm` на `from tqdm import tqdm`. Если обучение уже идёт, не перезапускайте ядро только ради полоски прогресса: перезапуск остановит вычисления.

### После переключения QUICK загружается неправильное число изображений

Локальная папка изображений общая для двух режимов. В ноутбуках добавлена проверка размеров подвыборки и наличия файлов: если локальные данные относятся к другому режиму, распаковывается соответствующий архив или создаётся нужная подвыборка. Проверьте вывод после загрузки данных: при полном запуске Flickr ожидается `train: 5000`, `val: 300`, `test: 1000`.

### Не хватает памяти

Сначала попробуйте `QUICK = True` и закройте другие процессы обучения. При необходимости уменьшите `BATCH_SIZE`, сохранив условие `QUEUE_SIZE % BATCH_SIZE == 0`. На MPS в медицинской части уже используются `MED_BS = 4` и `MED_ACCUM = 8`: эффективный батч равен 32, но одновременно в памяти находятся активации только четырёх примеров. Если памяти всё ещё мало, можно выбрать `2` и `16` соответственно.

### После изменения конфигурации используются старые значения

Редактирование текста ячейки не меняет уже созданные переменные. Перезапустите ядро и выполните ноутбук с начала.

## 10. Как вернуться к работе позже

Откройте папку проекта и выполните:

```bash
uv sync
```

Выберите ядро `.venv` и запускайте ноутбук. Повторять установку Homebrew, uv и Python не нужно. Активация через `source .venv/bin/activate` необязательна, если команды запускаются через `uv run`.

При переносе проекта сохраните `pyproject.toml`, `uv.lock` и `.python-version`. Папку `.venv` переносить не нужно: на другом компьютере её создаст `uv sync`. Данные и чекпоинты переносите отдельно, если хотите продолжить с готовыми результатами.

Полезные ссылки: [установка uv](https://docs.astral.sh/uv/getting-started/installation/), [управление Python](https://docs.astral.sh/uv/guides/install-python/), [uv и Jupyter](https://docs.astral.sh/uv/guides/integration/jupyter/).
